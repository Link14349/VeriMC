# VeriMC 编译器设计方案

版本：0.1，2026-09-07。用户已授权本方案及源码到逻辑图阶段的实现。语言语义以 languageSpec.md 为准；本方案规定实现分层，不修改语言的位宽、复位与采样含义。

## 1. 目标与交付边界

完整路线：`.vmc → AST → 展开后的类型化逻辑图 → .vmcl → 红石组件映射 → 布局布线 → 方块设计 → simulator 验证`。

本阶段交付独立 C++20 编译前端、命令行工具、可读且可验证的 `.vmcl` 逻辑中间体和回归测试。输出图中的寄存器与运算均为逻辑资源，无 Minecraft 坐标、红石延迟或器件选择。输出成功只表示选定顶层可生成逻辑图，不表示物理可实现或测试已通过。测试声明与物理 build 声明可以随源文件解析，但编译命令不会把它们当成已执行测试或物理约束验收。

物理 cell 需要模型及资产接入，目前应明确拒绝参与本阶段逻辑生成；不能替换成零或空节点。后端与 simulator 的序列化适配另行实施。所有实现、工具、构建缓存及测试均在 `verimc/`。

## 2. 解析工具选择

| 方案 | 可复用内容 | 项目取舍 |
|---|---|---|
| ANTLR4 C++ target | 根据文法生成 lexer、parser、解析树及 visitor/listener | 本阶段采用；文法可独立阅读，手写 C++ 不必大量使用模板 |
| lexy | C++17 解析 DSL、错误报告和语义回调 | 可行替代，但规则写进 C++ 模板，与现有独立文法的维护方式不同 |
| PEGTL | C++ PEG 组合器及动作 | 可行替代，也需要维护 C++ 文法与对应语义动作 |

ANTLR 的解析树包含语法包装和标点，不直接用作长期 AST 或输出格式。我们遍历解析树，复制为自有 AST，保留源区间，然后释放 ANTLR 的输入、token 与解析树。后续阶段不持有 ANTLR 指针。

ANTLR 不负责名称解析、位宽推导、寄存器语义、模块展开或电路综合。它生成的 visitor 是扩展接口，不能自动理解 VeriMC 的硬件含义。LLVM/MLIR、通用门级综合框架暂不作为依赖：当前需要的是类型化硬件图，而不是 CPU 机器码。

锁定 ANTLR 4.13.2 的生成器和 C++ runtime，下载内容用 SHA-256 校验。Java 只用于构建时生成 C++ 源码，运行 verimcCli 不需要 Java。构建缓存不入 Git。Boost.Multiprecision 用于编译期数学整数，nlohmann/json 用于 `.vmcl`，OpenSSL EVP 用于源文件 SHA-256。

参考（2026-09-07 核查）：[ANTLR C++ 文档](https://github.com/antlr/antlr4/blob/4.13.2/doc/cpp-target.md)、[官方版本下载](https://www.antlr.org/download.html)、[lexy](https://lexy.foonathan.net/)、[PEGTL](https://github.com/taocpp/PEGTL)。

## 3. 阶段与数据所有权

1. **读取及解析**：验证 UTF-8、语言版本与完整语法；读取显式导入，限制在项目根内，拒绝路径逃逸、导入环。错误包含文件、行列、UTF-8 字节区间。生成拥有数据的 AST。
2. **名称及编译期展开**：建立源文件与导入名称空间；选定顶层和命名参数。计算常量、类型大小、require、有限 generate 和实例参数；递归设计及预算超限终止。保留完整实例路径。
3. **类型及逻辑构建**：按规范推导每个表达式的类型；保留总线级 add、compare、mux 等节点；常量数学有定义，不依赖宿主溢出。if/match 降为选择关系，next 降为寄存器下一状态。
4. **连接检查**：按位检查唯一驱动与完整驱动；只允许合法端口方向。组合依赖检查需要按位追踪，不能把一个有部分接线的总线粗略当成一个依赖节点，否则会误报逐位进位链为环。
5. **时钟及状态检查**：寄存器只属于本模块的一个上升沿块，复位优先，未更新路径保持旧值；模块展开后所有状态归属同一顶层 clock。寄存器输出打断组合依赖。
6. **规范化输出**：稳定节点编号及顺序、相对源文件路径、源码 SHA-256 和展开路径；生成 `.vmcl` 前检查图完整性。固定源码、顶层、参数、预算及工具版本应生成相同字节。

核心库与 CLI 分离。AST 使用明确结构体与共享不可变表达式树；逻辑图使用稳定整数 ID 和标准容器。预算覆盖输入大小、递归深度、实例/generate 展开、图节点和信号总位数。首次失败终止该构建；不输出部分图冒充成功。

## 4. `.vmcl` 的粒度

`.vmcl` 是带类型的逻辑网表，首版采用 UTF-8 JSON。它既保留多位运算，也能表示逐位组合的连接；无需提前把加法器全部拆成与或非门。后续映射器可选择字级组件或再拆小。

图保存：顶层端口、实例元数据、信号、运算节点、源与目标位段的连接、寄存器的 clock/reset/resetValue/next、完整类型、源码位置及编译配置。纯 wire 与子模块端口保留命名锚点，方便诊断。模块逻辑展开到一张图中；实例树作为元数据保留。组合依赖的 DAG 与寄存器反馈边必须区分。

数组按元素、元素内最低位优先打包；类型仍保留数组身份。bit、level、clock、枚举不能混同；uint<4> 不等于一根 level。数字常量以十进制字符串保存，防止 JSON 消费者丢失大整数精度。编译期 nat/integer 在展开后消失，不占用电路资源。

未知格式版本、节点操作、非法引用或类型不一致必须拒绝。`.vmcl` 自带足够逻辑信息供独立消费者使用，不能要求消费者再次解析 `.vmc`。它不含 GUI 布局，也不含正在运行的寄存器值。

详细字段和运算定义见 [vmclFormat.md](vmclFormat.md)。

## 5. 寄存器的准确含义

寄存器节点输出旧状态，其 next 是组合图的结果。一次有效采样先根据所有旧状态求各 next，再共同提交。reset 为高时选 resetValue；使能关闭通过 next 选择旧值表达，不能生成门控时钟。

resetValue 不是上电初值。没有经历复位的寄存器在逻辑验证中无效；选择器只读取选中分支，复位可在不读取无效旧状态的情况下建立有效值。优化必须保留这种选择有效性以及规范周期数。本阶段优先输出可追踪、保守的图，不实施共享状态、流水化或重定时。

## 6. 后续物理阶段

映射器读取 `.vmcl` 和目标组件库，替换有证据支持的运算及寄存器。布局器先使用规则化区域及布线通道，路由器使用经过验证的连接组件。强度、支撑、方向、隔离、初始化和位置支持域均参与约束检查。

布线完成后检查数据路径、最小路径、时钟到达差、脉宽及复位，再用 simulator 运行完整方块事件。失败允许返回映射/布局阶段；不可暗中增加逻辑周期。最终输出 CircuitDesign 及端口/源码映射，蓝图导出由后续模块处理。

## 7. 验证与验收

- 与既有 Lark 文法核对正反例语法；ANTLR 是执行文法，Lark 是独立语法对照，修改时成对审查。
- 所有现有纯逻辑正例和教程生成图，包括位片连接、参数化实例、generate、枚举状态机和寄存器交换。
- 静态反例验证错误码；额外覆盖导入逃逸、未驱动、重叠驱动、组合环、递归、预算及非法运算。
- 独立图消费者验证四位加法器全部 256 组输入、逐位进位链、复位优先、计数回绕、保持、跨实例共同提交及有符号边界。
- 重复编译比较字节；检查源码位置、哈希、端口与寄存器信息；图重读验证拒绝未知版本和破损引用。
- Release 构建及 AddressSanitizer/UndefinedBehaviorSanitizer 检查。测试记录必须区分解析、静态、图行为和物理验证，物理部分本阶段无结果。

本阶段完成后先展示命令行及 `.vmcl` 样例；编辑器中的逻辑图排版、测试语言运行器、物理 cell 接入与优化器可沿稳定接口继续实现。
