# VeriMC 0.1 设计核查记录

日期：2026-09-07。本文件保留语言设计轮的核查记录，当时未实现编译器。其后已授权并实现源码到 `.vmcl` 的前端，最新结果见 [编译器实施记录](compilerStatus.md)。

## 1. 本轮完成的设计

| 主题 | 已明确的规则 |
|---|---|
| 词法与文件 | UTF-8、.vmc、版本头、名称、保留字、注释、字面量、文件导入 |
| 类型与运算 | 定宽数/位向量/level、枚举与数组、扩宽/截位、溢出、符号与移位 |
| 模块与展开 | 按名参数、有限生成、实例端口、驱动方向、部分连接和组合环 |
| 状态 | 显式寄存器、同步复位优先、使能保持、下一状态共同提交、单时钟 |
| 结构与实现 | 外部 cell、组件数据约定、版本库、布局约束、真实路由与时序失败 |
| 测试与调试 | 逻辑采样、真实 gt 周期/时间线、无效值、时序违规、错误和预算 |
| 接口 | 设计/快照分离、源码定位、必需元数据与 simulator 能力检查 |

这些规则组成 0.1 草案，不把初稿中的伪代码和本轮语法混为一套。未来增加多时钟、模拟量综合、存储器、异步自动综合或反向编辑属于明确的语言/实现扩展。

## 2. 检查方法

[checkSpec.py](../tools/checkSpec.py) 仅加载[文法](../grammar/verimcGrammar.lark)、解析样例、核对词法边界与本地链接，并独立计算示例方程。它不是 VeriMC 编译器，不进行类型推导、HDL 执行或物理仿真。

复现时使用 Python 3.9 或更新版本，以及 [specQaRequirements.txt](../tools/specQaRequirements.txt) 中固定的 Lark 1.2.2。在本轮临时依赖目录下执行：

```sh
PYTHONPATH=/private/tmp/verimcSpecQaDeps python3 verimc/tools/checkSpec.py
git diff --check
```

该临时目录不属于交付文件。其它机器可在独立虚拟环境安装上述 requirements 后直接运行脚本，不需要构建 simulator。

文法采用 Earley 解析与显式歧义检测。对样例检查单一解析树，只能说明这些样例没有发现歧义，不是对整门语言无歧义的形式证明。

## 3. 本轮验证结果

规范核查脚本通过：

- 22 份 .vmc 示例：19 份按文法接受，3 份语法反例按预期拒绝；已接受样例没有出现多棵解析树。
- 18 个独立词法边界：7 个正例接受，11 个反例拒绝，包括数字格式、保留字前缀、BOM 位置和尾逗号。
- 43 个文档本地链接和 6 个示例 import 路径有效。
- 四位加法方程的 256 对输入与整数运算一致；计数回绕和旧值交换预期一致。

所有语义反例的错误码目前为人工审阅后的预期，尚无静态语义检查器执行证据；物理示例缺少真实库资产，明确列在 reviewOnly 目录。文法“接受 19 份”包括语法合法但语义应失败的反例，不代表 19 份可用电路。

独立数学检查穷举四位加法的 256 对输入，将逐位全加器方程与整数加法比较，并核对计数回绕和寄存器旧值交换的预期。这不读取或运行 .vmc 文件，也不证明红石时序正确。

人工核对重点：加法结果扩宽和截位对应；两个子计数器共享同一时钟；reset 优先级与未复位诊断相容；独立 if 不产生隐式写优先；level 不隐式变成总线；clock 仅通过别名相连；测试驱动/采样顺序能明确对应到输入与输出。

## 4. 已知缺口与后续边界

- 尚无 VeriMC C++ 前端、静态检查器、逻辑执行器、组件映射器或路由器。正例中的 test 是待执行的测试描述。
- 真实寄存器/门组件、时序表征、空间规则验证器和目标输入适配器均需后续物理实现及 26.2 差分，不能依据示范周期或伪资产推导性能。
- simulator 正在独立实施。跨子项目设计包的具体序列化、无损 NBT 编码和输入观测 hook 需要在接入阶段形成版本化契约；本规范已经规定不能丢失的语义字段及不支持时的拒绝规则，未冒充这些接口已经稳定。
- 本轮没有证明任意电路的逻辑等价、物理时序或原版兼容性。场景通过、时序界证据和形式化证明的结论必须分别标记。
- 编译器实现尚未开始；本轮交付可供用户审阅的规范、文法、样例和规范核查工具。
