# 编译器实施与验证记录

日期：2026-09-07。实现：C++20 前端 0.1.0，ANTLR 4.13.2，`.vmcl` v1。授权范围为源码到逻辑图；物理后端未实施。

## 已实现

- ANTLR lexer/parser，拥有数据的 AST、UTF-8 字节源码区间、完整文件句法解析。
- 显式导入、项目根限制、导入环/重复名称检查、编译期常量、按名参数、require、有限 generate、模块展开和纯函数。
- bit/bits/uint/int/level/clock、名义枚举及一维数组的类型规则；显式转换、扩宽、截位、拼接、超宽移位和大整数运算。
- 逻辑条件、组合分支与 match 的选择网络；按位驱动完整性、重叠驱动和方向检查。
- 同步寄存器、复位值、下一状态、保持分支、统一时钟，保留“未复位无效”和共同提交的逻辑协议。
- 独立 `verimcIr` 库及共享 `LogicGraph`：类型/操作枚举、类型化属性、大整数、连接、端口、来源及预算；前端直接返回 IR，校验器直接消费 IR，JSON 适配器负责文件读写。
- `.vmcl` 文件输出与独立读取校验；按位组合环检查、操作签名、类型、常量、端口、时钟、文件来源和图预算检查。
- 确定性输出，源码 SHA-256、实例及源区间、JSON 错误诊断；保留可获得的冲突相关来源。
- CLI 的 parse / compile / validate；普通输出排他发布，`--force` 才允许替换。

## 实际验证

测试源为 `tests/compilerTests.py` 和独立图消费者 `tests/logicModel.py`。消费者只读输出 JSON，不调用编译器、不读 AST，也不使用源码解释器。CTest 注册 **4 个套件**：原有端到端套件包含 **20 个测试组**，另有独立 IR、前端 C++ API、JSON 适配器测试。

- 现有 22 份规范示例：19 份语法正例、3 份语法反例；7 份教程语法通过。
- 7 份纯逻辑示例中的 10 个模块全部可生成、重读 `.vmcl`；7 份教程的顶层全部可生成。
- 字级四位加法器、逐位进位四位加法器分别穷举 256 组输入；八位参数展开检查最大值进位。
- 有符号四位运算穷举 256 对输入，检查扩宽加减、取负、回绕及符号右移；检查 4096 位类型和大于 128 位的常量。
- 计数器复位优先、使能保持、回绕、再次复位；寄存器交换共同提交；跨模块计数连接；枚举状态机。
- 数组接线、带状态数组、枚举选择、位拼接、纯函数、分片组合驱动，以及逐位依赖链无假阳性环。
- 原有静态反例和新增方向、作用域、参数、递归、位宽/索引、预算、BOM、非法词法、导入逃逸及导入环反例。
- 编译期条件/逻辑短路的有效性：未选除零可被避开，选中除零与未选分支里的静态非法运算仍报错。
- 重复构建及移动项目根后生成相同字节；源码哈希和 UTF-8 区间；失败保留旧产物及排他写入。
- `.vmcl` 未知版本/操作、悬空引用、重复/缺失驱动、非法状态协议、重复 JSON 键与过深 JSON 被拒绝。
- 中文诊断说明、冲突的实例路径、源码哈希和相关源区间检查。
- 无 JSON/ANTLR 的原生消费者直接构图、校验与修改连接，检查 `x ^ 0 → x` 前后真值；合法寄存器反馈与非法环、属性、引用、驱动、类型和常量反例。
- 前端 C++ API 只链接 `verimcCore`，得到 IR 后直接读取/修改寄存器属性；JSON 大整数/参数往返和导出前校验。
- 旧版计数器 `.vmcl` 兼容夹具经过 IR 导入/导出后字节一致；重构前保存的 16 份不同样例产物与新编译输出逐字节一致。

构建环境：macOS arm64，AppleClang 17.0.0。**Release 与 Debug + AddressSanitizer/UndefinedBehaviorSanitizer 的四个测试套件均通过；关闭编译器和 JSON 适配器后的独立 IR 构建及测试也通过。** 未做编译器性能倍数声明，也未验证其它平台的构建与发布行为。

独立 Lark 文法/文档核查命令：

```sh
PYTHONPATH=verimc/.cache/specQa python3 verimc/tools/checkSpec.py
```

Lark 版本由 tools/specQaRequirements.txt 锁定为 1.2.2；它只用于规范交叉核查，生产编译器不用 Python。实际结果：19 份语法接受、3 份预期拒绝，无已接受样例解析歧义；额外词法边界 7 份接受、11 份预期拒绝；82 个本地文档链接通过。

## 明确边界与后续工作

1. 编译命令对**选定顶层展开后的纯逻辑设计**做语义检查；未实例化的模块体和未调用函数不做全项目实例化检查。未实例化物理声明和测试正文只做句法检查。
2. `.vmc` 中的 logical/physical test **尚无原生执行器**。上述行为结果来自独立 `.vmcl` 测试消费者，不能说源码测试已执行。未复位检测属于逻辑执行阶段，不是编译时将寄存器置零。
3. 物理 cell 的资产/模型接入未实现，选中设计使用 cell 明确报 EModelMissing；build 不执行器件选择、空间或时序检查。
4. 红石组件映射、门级优化、布局布线、simulator 适配和蓝图导出仍未实现。`.vmcl` 可被读取和检查，不代表真实方块电路已生成。
5. 当前输出首个阻断诊断；多错误恢复、WUnused/WStyle 告警、编辑器中的逻辑图布局及增量编译仍待后续实现。
6. 未提供“所有输入都等价”的形式化证明；本记录只声明列出的结构与行为测试范围。组件相关的 26.2 物理兼容验证不属于此次交付。
