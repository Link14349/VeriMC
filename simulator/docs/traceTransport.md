# 探针历史与接收确认

## 已实现的行为

原生内核默认保留最近 500,000 条探针边沿。没有接收方时按容量淘汰最旧历史；存在浏览器时，只有所有接收方都确认过的边沿才能淘汰。接收确认取各窗口游标的最小值，快速窗口不能替慢窗口释放数据。

未确认边沿达到容量后，完成当前原子器件更新及其同步邻居更新，然后暂停。后续计划事件保留在队列中；再次单步也不能绕过等待。收到正确确认后，用户可继续运行。两秒未确认或者所有窗口断开，也会暂停并给出原因。普通历史滚动淘汰仍然存在，不等于无限保存波形。

单次更新可能同时产生多个边沿，因此在历史容量外预留 65,536 条安全余量。超过这一余量会明确中止执行，禁止继续运行，需撤销或恢复有效快照；这是有界内存下的保护限制，不能声称该极端情况可无损续跑。服务端批量编辑属于一个事务，出错会回滚整个编辑。

原生调用者使用 `retainTraceFrom(firstUnacknowledged)` 开启保护；用空值解除传输保护。`traceBlocked()` 表示未确认记录已满，调用者应在新的外部编辑前检查。服务端已检查运行、单步、放置、移除、交互、刺激和增加探针等命令。原生器件内部的同步更新不能在中途停下，因此底层方块修改函数不使用此条件打断调用栈。

## 协议 3

连接的 `ready.protocolVersion` 为 `3`。方块二进制布局继续使用 `VMC2`，含帧号、全量/增量标志、游戏刻与修订号。每帧最后一定发送 JSON `trace` 消息，空采样帧也不省略：

```json
{"type":"trace","frameId":12,"epoch":4,"from":100,"next":102,"reset":false,"edges":[[1,20,44,15],[1,20,45,0]],"dropped":0}
```

每条边沿为 `[probeId, tick, sequence, value]`。`from`、`next` 为本代历史的全局半开区间，`next - from` 必须等于边沿数量。浏览器校验帧号、代号、游标和同刻顺序，完成场景缓存与采样历史处理后才发送：

```json
{"cmd":"ack","frameId":12,"epoch":4,"traceEnd":102}
```

三者必须匹配唯一在途帧。旧版只带帧号的确认、错误代号或错误结束游标均不释放记录。确认表示显示数据已接收和处理，不要求等待屏幕完成绘制；屏幕绘制独立按浏览器动画帧执行。

清除采样、加载工程、撤销或重置会产生新的历史代号。若旧帧仍未确认，全量刷新等待确认后发送；不能覆盖在途帧造成游标混淆。断线重连通过全量帧恢复当前保留历史，过期历史不会伪装成仍然存在。

服务端 `traceBudget` 命令允许设置 256–500,000 条容量，便于测试和控制记录预算；目前没有界面选项。运行快照保留容量外原子余量，不静默裁剪；超出当前容量与余量的导入会报错，可先增大容量再导入。

## 浏览器历史与绘制

浏览器独立保留最多 500,000 条边沿，用追加数组和定期压缩代替每批复制全部历史。每个探针建立索引，时间窗通过二分查找定位；不再对每个通道扫描所有探针的历史。被截断的通道最后电平只作为仍保留时段的起始状态，不补画已经过期的时间区间，也不把未知电平画成零。

界面显示“显示历史已截断 N 条”，统计浏览器实际截断量。原生 VCD 导出基于内核保留历史，因此内核容量调小时，其导出范围可能比已连接浏览器中的范围短。最大时间窗内边沿非常密集时，Canvas 绘制成本仍与窗内边沿数相关；逐像素聚合和大型场景完整性能验收尚未完成。

## 验证

- 原生测试覆盖一次事件超出软容量、未来事件保留、确认后的精确续跑、快照余量往返、硬余量中止及无事件时禁止跳过暂停。
- HTTP/WebSocket 测试覆盖真实侦测器时钟、错误确认、逐条边沿比较、恢复运行、旧帧期间重置，以及多个窗口取最慢确认游标。
- 前端测试覆盖同刻边沿、乱序/缺帧拒绝、历史截断与起始电平、51,200 条连续追加后的索引一致性，以及确认必须发生在采样处理之后。

```sh
python3 simulator/tests/serverTests.py
python3 simulator/tests/backpressureTests.py
node simulator/tests/webTests.mjs
```

集成测试需启动本地服务；可追加端口参数，在独立测试服务上运行。
