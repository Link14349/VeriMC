# 音符盒

音符盒支持红石上升沿演奏、手动调音、只演奏不调音，以及上下方变化引起的乐器选择。工程菜单的“音符实验”提供铜块音符盒—感测体—比较器—红石灯电路。浏览器不播放声音；检查面板显示已执行次数和最近的演奏时刻、乐器、音符与音高倍率。

## 原生行为

- 读取上方方块的乐器；如果它是头颅乐器，优先采用，否则读取下方材质。头颅在下方时回退竖琴。新放置和上下方形状通知执行此选择，原始状态编辑仍允许显式乐器属性。
- 普通乐器要求上方为空气，玻璃、地毯等同样会阻止触发。头颅乐器允许上方非空气。保持供电时移去遮挡不产生新的上升沿。
- 手动操作把音符在 0–24 间循环，并尝试演奏。`stimulate: {"playNote": true}` 对应只演奏当前音符。
- 触发时立即产生 `NOTE_BLOCK_PLAY` 游戏事件，再于方块事件阶段执行声音结果。同一坐标、类型和参数的待执行事件去重，但各次触发仍独立发出振动。
- 方块事件读取执行时的音符和乐器；触发后调音或放入遮挡不会简单地取消已经排队的声音。实际声音执行按原版显式调用世界随机源的 `nextLong`，不能当成其他方块常用的独立声音包随机源。
- 感测体接收的演奏频率固定为 10，与音符 0–24 和声音音高无关。

`noteRules.json` 从固定 Java 26.2 导出全部 1,196 种方块的基础乐器、27 种乐器元数据和 25 个原版单精度音高值。包括铜块及其氧化阶段的小号音色。器件库新增常用乐器底座和头颅；沙、砂砾等下落方块尚未开放，军鼓可通过音符盒原始乐器属性测试，不能因此声称已支持下落方块物理。

## 头颅与恢复

六种生物头颅及玩家头颅可作为音符盒上方乐器。玩家头颅的环境面板接受 `customSound` 资源标识符或 `null`，例如 `simulator:test/bell`。缺少声音标识符时仍发出音符盒游戏事件，但不执行声音输出，也不消耗该声音的世界随机数。标识符作为数据保存，不下载或执行资源包。

运行快照保留待执行方块事件、随机状态、自定义声音和最近演奏信息；非法记录整体拒绝。等待演奏时导出电路会提示保存快照；普通电路文件清除过去演奏的诊断记录。头颅的生物生成、皮肤、嘴部动画和资源包声音播放未实现，器件覆盖仍标记部分支持。声音播放是 UI 附加项，不是振动触发的来源。

## 验证

- `captureNotes.py`：原版 GameTest 100 刻 / 34 点，对照材质变化、四种铜小号、头颅优先级、遮挡、上升沿、25 次调音循环及感测体/比较器状态。
- `ExportNoteRandom.java`：原版方块事件的 112 次独立调用，覆盖 27 种乐器、四个随机种子以及玩家头颅有/无自定义声音，逐次比较执行结果和随机状态。
- 原生专项验证待执行事件去重、执行时状态、事件前加遮挡、快照续跑、非法输入原子拒绝以及头颅移除。Release 与 ASAN/UBSAN 共 70 项测试通过。
- `noteTests.py` 验证调音、去重、快照、振动、遮挡与头颅接口；振动、完整服务和投掷器回归通过，前端生产构建通过。
- 浏览器实操调高一音：1 gt 显示小号、音符 1、倍率 0.5297；4 gt 感测体输出强度 8、频率 10，波形同步，控制台无错误。

规则依据为固定服务端的 `NoteBlock`、`NoteBlockInstrument`、`SkullBlockEntity` 以及方块注册属性。原版源码、资源与 JAR 不随项目分发。
