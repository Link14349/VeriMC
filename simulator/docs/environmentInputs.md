# 环境输入与器件边界

本地 C++ 内核执行器件状态和时序。浏览器提供输入，不直接计算输出。目标仍为 Java 26.2 非实验性红石。

## 已开放的输入

| 器件 | 输入 | 内核行为 |
|---|---|---|
| 普通压力板 | 触及检测区域的实体总数、生物数 | 木质板计全部实体；石质及磨制黑石板计生物。首次触及立即激活，激活后每 20 gt 重新检测。 |
| 测重压力板 | 同上 | 轻质上限 15、重质上限 150；按原版浮点计算向上取整至 0–15。激活后每 10 gt 重新检测。 |
| 避雷针及铜变种 | 一次雷击 | 8 gt 供电；已有计划刻时，再次雷击不延长原有结束时刻。 |
| 阳光探测器 | 有效天空亮度 0–15、太阳角度 0–360° | 在下一次 20 gt 边界计算；反向模式切换立即计算。默认实验环境亮度为 0。 |
| 讲台 | 放入 1–100 页书、取出、翻到某页 | 比较器输出按页进度计算。翻到不同页产生 2 gt 脉冲；重复翻页不延长已计划的结束时刻。界面页码从 1 开始，内核 `page` 从 0 开始。 |
| 标靶 | 命中强度、是否为箭 | 箭 20 gt，其他投射物 8 gt；脉冲内的再次命中不覆盖已有输出。 |

压力板数量已排除旁观者与忽略方块触发的实体。实体进入、离开由用户输入，不模拟移动轨迹、碰撞或 AI。库存中的一叠物品也不能当成多个掉落实体输入。

阳光探测器输入的是原版公式使用的**有效天空亮度**，不包含从天气、遮挡、天空光传播计算这个数值的世界仿真。输入恒定时，首个检测后省略不会改变状态的重复检测；下一次输入重新安排检测。使用原版 Mth 表索引和单精度运算，721 个角度 × 16 种亮度的数值对照通过；这不是天空光传播的兼容性声明。

## 方块属性驱动的读数

炼药锅液位、蜂箱/蜂巢蜂蜜等级、重生锚充能、末地传送门框架中的眼和铜傀儡雕像姿态，可以在属性面板编辑，比较器读取其真实状态公式。不会因此运行完整流体、蜜蜂 AI、传送门、爆炸或铜傀儡 AI。未模拟自然氧化和随机刻。

这些器件注册为 `externalStimulus`，与完整红石器件状态机区分。其他尚未实现的器件仍拒绝放置与导入。

## 门的交互

普通门、铁门和铜门支持两格放置、上下状态同步、任一半部受电和支撑丢失。木门/铜门、活板门和栅栏门支持手动操作；铁门/铁活板门需要供电。编辑器没有玩家实体，朝向、门轴由搭建属性决定。没有完整墙体器件库，栅栏门的 `in_wall` 当前作为显式状态。

## 验证

- `java26_2Devices.json`：原版 GameTest 中执行 29 刻、32 个观测点。压力板使用真实盔甲架和独立掉落实体；环境输入触发原版方法，原版计划刻负责后续运行。
- 覆盖门上下半部、受电时手动操作、支撑消失、普通/测重压力板、重复雷击、讲台翻页与取书、隔一格实体方块的比较器更新。
- 跨所有朝向、位置和交叉触发的穷尽验证仍未完成。三维模型是便于搭建的独立几何外观，不是原版纹理或完整碰撞模型。
