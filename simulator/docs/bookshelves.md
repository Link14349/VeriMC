# 雕纹书架

雕纹书架有六个物理槽位，每槽一本书。接受的五种默认物品由固定 26.2 JAR 的 `bookshelf_books` 物品标签导出：书、书与笔、成书、附魔书、知识之书。非法物品或超过一本的输入整批拒绝。

比较器读取最后一次操作的槽位编号：初始为 0，操作第 1–6 槽后输出 1–6。取走最后一本书仍保留该编号；重复清空已经空的槽不改变编号。批量编辑保留用户提交的操作顺序，不能按槽号排序。运行快照和电路文件保存最后操作槽位，即使书架已经空了也不会丢失。

漏斗和投掷器只能向空槽插入标签内的书。漏斗从书架抽取前检查自身是否存在可接收整本书的槽位；检查失败不取出再放回，也不改变最后操作槽位。这种无副作用的失败可以休眠；接收库存发生变化时局部唤醒，避免空转扫描。普通容器原有的失败取出/恢复通知不受影响。

书架每次实际写入或取出都会更新六个占用属性；比较器输出不按填充率计算。编辑器提供 3×2 槽位、限定书籍的物品建议和程序绘制的书脊。当前接口是库存编辑，尚未提供基于点击位置的玩家持书交互；内部 `BLOCK_CHANGE` 游戏事件和声音待统一事件系统补齐，所以器件标记为部分支持。带自定义组件的书籍仍明确拒绝。

## 验证

`captureBookshelves.py` 在原版运行 57 刻 / 11 点，覆盖五种书、批量操作次序、取空后的读数、漏斗输入与抽取预检查、容量变化唤醒、投掷器拒绝非书及接受知识之书。每刻比较方块状态、模拟输出和物理槽位。

原生测试额外检查非法批量输入原子性、空书架快照保留历史、阻塞漏斗推进 10,000 刻仅处理一次检查事件、容量变化后的续跑一致性。WebSocket 测试覆盖编辑、拒绝、清空和快照恢复。浏览器实操第六槽写入一本书并清空：占用状态和书脊消失，比较器与探针仍为 6，控制台无错误。

规则依据：26.2 的 `ChiseledBookShelfBlock`、`ChiseledBookShelfBlockEntity`、`ListBackedContainer`、`HopperBlockEntity` 与原版物品标签。原版源码和资源不随项目分发。
