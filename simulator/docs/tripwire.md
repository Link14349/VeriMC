# 绊线与绊线钩

实现目标为 Java 26.2 的方块电路行为。`tripwire.cpp` 处理连接、检查、供电和拆除；实体只通过显式接触输入参与。

## 搭建和电路行为

- 绊线钩朝向指向线段，背面需要完整支撑面；绊线本身不需要地板。两钩之间允许 1–40 格绊线，零格与 41 格均不连接。
- 编辑器放置最后一个钩也会触发原版 `setPlacedBy` 对应检查。绊线的四向外观根据邻格绊线或朝向相对的钩更新。
- 绊线变化按原版顺序向南、向西寻找钩；连接检查保留原版扫描、通知和交叉线的更新顺序。不会把整个网络简化成一个逻辑开关。
- 有效实体接触后，绊线进入触发状态。激活的绊线每 10 gt 复查。绊线钩向各方向弱充能，向背部支撑强充能，强度为 15；绊线本身不输出红石电力。绊线探针显示的是内部触发状态，便于调试。
- 普通移除绊线按“被触发的线段”通知钩，从而产生断线脉冲。脉冲在钩下一次计划检查时结束；已有计划可使时长短于新安排的 10 gt。剪刀先设置 `disarmed`，再拆线，从而解除该段断线触发；其他仍被接触的线段照常工作。
- 钩的支撑消失时，按破坏流程通知其他器件。通用形状更新产生空气时也采用破坏通知，避免仅换成空气而漏掉电路更新。

## 输入与恢复

对绊线使用 `stimulate`，输入二选一：

```json
{"entities": 1}
```

```json
{"shear": true}
```

`entities` 是已经过滤“不触发方块”的实体后，触及本段检测体积的数量；范围为 0–1,000,000，0 表示全部离开。输入保持到下一次修改或器件移除。没有实体移动、掉落轨迹或生物 AI。

释放检查会安排原版的零延迟复查，实际在下一游戏刻执行。在这一刻之前再次进入，不能绕过待执行检查而立即激活；输入驱动在下一刻的接触阶段重试。阶段顺序是计划刻、方块事件、外部接触、方块实体；这样重新接触引起的活塞动作也不会提前到已经结束的方块事件阶段。接触阶段记录于运行快照，按输入排期序号执行；它不代表完整的原版实体遍历模型。

浏览器提供数量输入、离开和剪断按钮，以及“绊线实验”。绊线使用原版附着/松弛选取体积，细线周围的格内区域也可点选；深色与橙色分别显示未触发和触发状态。

## 验证与当前边界

`captureTripwire.py` 在原版 GameTest 运行 70 刻 / 121 点，实体为不受重力影响的真实盔甲架，覆盖双轴、交叉、最长/超长线段、重新接触、剪断和支撑移除。拆钩会产生随机掉落物，因此本场景显式清除掉落物，隔离受控的实体输入；此选项记录在对照文件中。没有把随机掉落物碰线当成已模拟行为。

原生测试另外覆盖拆线瞬态、剪断无假脉冲、接触阶段的活塞时序、内部触发与电力输出区别、快照续跑和非法输入的原子拒绝。

声音、绊线产生的游戏事件向幽匿感测体传播及其随机数消耗尚待事件系统实现，不在本批次的兼容声明内。
