# 铁轨与矿车接触输入

已实现普通铁轨、动力铁轨、探测铁轨和激活铁轨的器件行为，以固定 Java 26.2 为准。

## 连接与供电

轨道放置保留原版连接协商顺序，包括直轨、弯轨、四个方向的坡道、软连接整理和三岔路的红石切换。移除下方支撑或坡道高端支撑会按邻居更新移除轨道。铁路状态改变时的移除通知也参与更新，不能仅在方块类型改变时通知。

动力轨和激活轨只沿相同种类、方向相容的已供电轨道寻找电源，每个方向最多追踪 8 条连接。两种轨道可以物理连接，供电不会互相串通。它们的 `powered` 状态可以在检查器、三维颜色和探针中观察，但不会被当成向相邻红石器件输出的弱/强信号。

激活铁轨的 `powered` 状态是留给外部矿车环境的激活接口。当前不执行乘客弹出、TNT 矿车引燃、漏斗矿车启停或完整矿车运动/碰撞。

## 探测铁轨

输入是已经通过原版接触范围筛选、按实体查询顺序排列的矿车列表。无接触时为 `[]`。支持普通、箱子、漏斗、熔炉、TNT 和命令方块矿车的接触类型。

命令方块矿车的比较器读数是它内部命令方块的 `successCount`。本项目**没有命令解释器**，该计数作为显式外部输入给出（`{"type":"command_block_minecart","successCount":7}`，限 0–15），与讲台页数、标靶命中同属受限实体输入。原版 `DetectorRailBlock.getAnalogOutputSignal` **先找命令方块矿车**，找到就直接返回它的计数，容器矿车根本不参与比较；这条优先级已在原版差分里验证。

```json
{"carts":[{"type":"chest_minecart","inventory":[{"slot":0,"item":"minecraft:stone","count":64}]}]}
```

箱子矿车使用 27 槽，漏斗矿车使用 5 槽。物品和堆叠规则与容器模块一致；保存实际槽位，比较器选择列表中的第一辆容器矿车，按原版顺序和单精度填充率计算读数。正常矿车本身不提供库存读数。

修改第一辆容器矿车的部分槽位：

```json
{"cartInventory":[{"slot":0,"item":"minecraft:ender_pearl","count":16}]}
```

进入会立即触发检测；激活期间每 20 gt 检查一次，离开不会立即清除轨道供电。矿车列表改变会影响直接查询的模拟读数，但比较器邻居通知由检测周期发出，不能每次库存编辑都强行立即通知。轨道输出弱信号 15，并向下强充能；比较器仍读容器库存，不能拿激活信号替代库存值。

浏览器提供普通/箱子/漏斗矿车进入、全部离开及矿车库存编辑。三维矿车是静止接触标记，不是运动仿真对象。输入矿车库存不参与方块漏斗与实体容器之间的转移；含水属性保存，但不模拟水流。工程菜单中的“铁轨实验”包含供电距离、激活轨、三岔路和比较器读数。

## 验证

`captureRails.py` 运行原版 Java 26.2，共 45 个逐刻观测帧、95 个位置，比较所有方块状态及模拟读数。覆盖两类供电轨的距离与隔离、岔路切换、四向坡道、支撑破坏、真实普通/箱子/漏斗矿车的接触和库存，以及真实命令方块矿车的三档 `successCount` 读数与「命令方块矿车优先于满载箱子矿车」。参考矿车不受重力且位于平直探测轨，避免将运动模型混入器件测试。

独立内核测试另外覆盖多矿车列表的容器选择、无效库存输入的原子性、延迟释放、快照续跑，以及供电轨不能向外输出普通红石信号。浏览器实操验证进入、写入 64 石头、20 gt 检测与比较器延迟、离开后的延迟释放。复杂轨道网仍需要更多差分覆盖，这些场景不等于完整矿车机器兼容。
