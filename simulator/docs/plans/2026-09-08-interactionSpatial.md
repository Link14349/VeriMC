# 交互与三维物理设计 Implementation Plan

**Goal:** 同步推进可用的三维编辑工作台与可追溯物理实现，按证据分阶段验收。

**Architecture:** 浏览器继续只负责编辑、预览和显示；C++ 保持仿真权威。逻辑 IR、组件映射、物理布局和方块执行保持独立，空间预览不代表物理验证通过。

**Tech Stack:** C++20、TypeScript、React、Three.js、Node 测试、浏览器实操。

## 授权与分工

2026-09-08 用户要求前端交互和三维红石设计协调推进，指定 Claude CLI Opus 承担大部分工作，Codex 亲自处理三维渲染与困难特性。仅使用真实 Claude CLI；不替换为 Codex 子代理。独立 worktree 隔离修改，主代理审查、测试后集成；不推送远程。

## M1：交互一致性和三维编辑基础

### Task 1：Opus 实现前端交互

文件：simulator/apps/web/src/main.tsx、styles.css，可新增 interactionState.ts；测试放 simulator/tests/interactionTests.mjs。

1. 阅读 AGENTS.md、README 与前端状态处理。
2. 修复选中对象与待放置对象混淆、Esc 清理、默认属性、快捷键焦点与帮助弹窗隔离、搜索 /、平台快捷键、Y 整数边界。
3. 展示器件支持等级，不能把 implemented 写成完全验证；补充搜索空态和当前工具文字。
4. 统一断线时的命令可用性，保留错误和暂停原因。
5. 添加行为回归，执行 npm run build、node simulator/tests/webTests.mjs 及新增测试。
6. 不修改 viewport.ts；主代理将提供 setPlacement(name, properties) 接口，调用处待集成验证。

### Task 2：Codex 实现三维视口

文件：simulator/apps/web/src/viewport.ts；浏览器测试放 simulator/tests/viewportTests.mjs。

1. 编辑网格跟随 Y 层，合法范围统一。
2. 真实方块简化预览复用现有渲染语义，输入/输出方向可辨认；不得把前端预览当作合法性判定。
3. 切换器件、工具、编辑层时立即刷新预览，不依赖再次移动鼠标。
4. 定位、剖切与负坐标拾取回归；所有显示变化不改变仿真坐标。
5. 通过类型检查与行为测试，进行浏览器交互和视觉验证。

### Task 3：集成与交付

审阅双方差异，运行全套现有前端测试和新增测试；记录真实浏览器覆盖及未测范围。按有意义更新提交，完整提交说明不超过 20 字符。

## M2：物理组件与连接闭环

在 verimc/ 内实现现有 physicalSpec.md 约定的组件读取、空间占用与接口映射；先验证有限组件与跨层连接，再做固定位置的受限路由。组件证据缺失必须显式标记，不得制造版本哈希或通过记录。主代理负责隔离规则、初始化与时序关键实现；Opus 负责常规适配、诊断界面、文档和测试。

验收：一个小组合电路跨层连接，生成真实设计及 sourceMap/interfaceMap，按照初始化计划运行，与逻辑接口结果比较。单独记录空间合法性、仿真场景通过与原版差分证据；不能混称完全等价。

## M3：受限自动布局与同步电路

以验证后的组件和路由资源图为前提，加入分层布局、时钟/复位与采样约束；禁止隐式流水化。搜索失败区分约束冲突与预算耗尽。以同功能单层设计比较体积、材料、跨层连接和时序，不预设三维一定更优。
