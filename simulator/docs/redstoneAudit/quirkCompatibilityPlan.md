# 原版特性保留与审计后续

目标是尽量复现 Java 26.2 非实验红石的可观察行为，包括玩家利用的准连接、黏性活塞短脉冲吐块、脉冲延长和更新顺序效应。原版中的 bug 不能仅因其不符合直觉而被消除。当前不是完整兼容认证。

## 为什么逐函数对应仍需验证

完整的状态转移等价，在相同初始状态和输入下应当产生相同特性；实际困难是证明翻译与抽象保持这种等价。仅对应方块函数不能覆盖调用上下文、邻居通知源、入队时状态快照、计划刻优先级和去重、方块事件与实体阶段、放置历史、区块可执行条件及随机源消耗。

C++ 的整数溢出、移位、负坐标除法、浮点求值和容器遍历也不天然等于 Java。逐函数审阅是主要证据之一，原版差分用于发现遗漏和翻译错误；典型机器用于验证组合行为，三者相互补充。

## 实施顺序和验收策略

1. 修复 R6、R7、R10 三个实际反例，并保留失败场景作为回归来源。
2. 核对更新执行主干：setBlock 的 flag、通知顺序和来源、递归更新栈、状态快照、计划刻的入队/收集/执行、方块事件阶段、移动方块收尾。逐个为 R1–R5、R8、R9、R13 建立可达反例；没有反例时保留静态证据级别。
3. 增加可开关、容量有限的刻内事件跟踪：记录 gt、阶段、序号、事件类型、坐标、通知来源、处理前后状态、排刻时间与优先级、必要的 RNG 消耗。参考游戏在相应调用点采集匹配轨迹；先核对跟踪器不会改变事件顺序。容量耗尽明确停止记录并标记不完整，不能把截断轨迹判为通过。
4. 在受限共同器件集内生成合法小电路与输入历史，以相同种子、绝对坐标、放置顺序对照 Java/C++；出现差异后缩减为最小电路和最短历史。不能只随机生成终态，必须覆盖更新过程。此测试设施尚未实现。
5. 建立真实机器回归：复杂 BUD、侦测器与活塞交错、零刻脉冲/活塞事件取消、黏液蜂蜜牵引、方向和位置相关线路。覆盖六朝向、负坐标、多个绝对坐标、多个合法放置历史；旋转后的预期仍从原版取得，不能强求方向不变。
6. 对依赖区块的机器先识别触发条件，再设计最小加载/卸载、可 ticking 条件、保存恢复和队列持久化模型。在模型缺失时明确标为未支持，不能用永远加载的世界宣称通过。

新增模型是后续设计/实现任务，本次只交付审计与 issue。每个修复须通过原版反例、新回归及相关既有测试，性能优化另给出等价条件和 Release 测量。

## 本次新增原版对照

| 场景 | 范围 | 结果 |
|---|---|---|
| stickyPulseMatrix | 六朝向 × 0/1/2/4 gt 脉冲，24 个黏性活塞布置，15 帧 × 72 点 | 全部匹配 |
| quasiConnectivityMatrix | 六朝向；上方隔格供电及后续邻居通知，17 帧 × 12 点 | 全部匹配 |

合计 1,284 次位置/帧观测，哈希、原点、环境见 [quirkDifferentialResults.json](quirkDifferentialResults.json)。0 gt 指同一命令回调内通断，不能外推为所有零刻机器。上向活塞的头部可能改变通知路径，不把六朝向都解释成完全相同的 BUD 延迟。

既有 22 个通过场景和 3 个失败反例保持原记录；新增 2 个通过场景没有修复这 3 个问题。既有准连接、短脉冲、脉冲延长、锁定和火把烧毁的具体场景也不能证明所有组合。逐刻末状态比较不能排除刻内多发/漏发脉冲。

## 明确例外与未完成范围

- R11：更新预算耗尽时暂停并保留状态，是当前 AGENTS.md 要求。不会为了模拟更新抑制而丢事件继续运行。更新抑制还有其他触发路径，需要分类，不能一概等同于预算耗尽。若未来要求复现该行为，须先重新讨论运行模式与这条约定。
- R12：振动空闲刻跳过是有前提的优化，不是已确认故障；需保持选择器为空且无行进中事件的条件。
- R14：未实现器件目前拒绝放置；枚举和库存容量占位不代表功能完成。
- 区块生命周期、实体输入与自动振动来源尚有缺口；不把它们概括成用户全部排除。
- TNT 复制机、流体农场、矿车计算机、依赖完整生物 AI 的机器仍是明确暂不实现范围。实验红石和 Bedrock 不属于兼容目标。

待核对的仅定位区域还包括计划刻部分细节、RailState.place、绊线/绊线钩、音符盒/钟。日光三角表 R15、flag 128 主线可达性尚待验证，不能宣称已经有可观察故障。
