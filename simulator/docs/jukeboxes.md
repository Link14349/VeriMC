# 唱片机

唱片机支持 26.2 的全部 22 张默认唱片、单槽库存、播放计时、直接供电、比较器和漏斗/投掷器传输。浏览器检查面板可以插入、替换或清空唱片，并分别观察播放进度、直接供电和唱片读数。

## 信号与计时

播放时向六面输出 15 的弱信号，不提供强信号。比较器读取唱片定义中的 1–15 输出，与播放状态分开；播放结束后仍保留唱片及比较器读数。下方漏斗会被播放信号锁定，结束后解除。

曲目长度来自固定版本的 `jukebox_song` 数据，按原版单精度乘法再向上取整得到游戏刻。播放额外保持 20 gt；在结束阈值所在刻仍为播放状态，下一个方块实体刻停止。例如第 0 gt 手动插入 `music_disc_11`，第 1 gt 首次计时，第 1441 gt 停止。重新写入同一张唱片也会重置进度。

`has_record` 控制方块实体的执行注册。由无变有时获得新的执行顺序；由有变无时注销；唱片自然结束但仍在槽内时保留顺序。方块实体阶段中首次注册的播放任务从下一刻执行，不能插到正在执行的列表末尾后立即运行。原始状态编辑把 `has_record` 改为假时暂停计时，已经存在的播放对象及直接供电仍保留；重新设为真后续播。

每次库存写入发出 `BLOCK_CHANGE` 游戏事件，包括空槽再次写空。原版周期性 `JUKEBOX_PLAY` 和 `JUKEBOX_STOP_PLAY` 不属于感测体监听标签，不会持续触发幽匿感测体。播放粒子在经过的刻数为 0、20、40… 时各消耗一次世界 `nextInt(4)`，即使没有客户端也保留随机消耗。

## 库存与文件

```json
{"inventory":[{"slot":0,"item":"minecraft:music_disc_bounce","count":1}]}
```

只接受一张具有默认播放组件的唱片；未知物品、普通物品、自定义组件和超出容量的修改均原子拒绝。投掷器和漏斗插入要求空槽；漏斗从唱片机抽取前要求接收容器至少有一个完全空的槽，仅已有堆叠的剩余容量不够。

运行快照保存唱片、播放进度、首次执行时刻、动态注册顺序和唤醒事件，并检查相互一致。电路工程保留唱片，载入时从头播放；`has_record` 与库存不一致的状态必须保存成快照。空闲唤醒时间存为 JSON `null`，避免浏览器把内部 64 位最大值舍入；漏斗和感测体快照同步修复，仍接受旧原生文件中的精确整数哨兵值。

当前空唱片机和播放结束的唱片机没有逐刻事件。播放中的器件仍逐刻执行轻量计时，保留阶段、重新注册和随机调用顺序；尚未把活动播放优化为每 20 gt 跳跃，不能据空闲休眠宣称活动性能达标。

## 范围与验证

器件标记部分支持。当前库存操作是编辑器修改，不生成玩家取盘或破坏时的掉落实体；尚无浏览器音频、材质资源复制、自定义物品组件和生物响应。

来源为固定 Java 26.2 的 `JukeboxBlock`、`JukeboxBlockEntity`、`JukeboxSongPlayer`、`JukeboxPlayable` 与 `LevelChunk` 执行任务注册规则。

- `exportJukebox.py`：22 个曲目和 22 张默认唱片，记录长度、声音 ID 与比较器输出，不复制音频资源。
- `ExportJukeboxPlayback.java`：原版隔离完整播放，22 张唱片共 4,265 个样本，比较长度、进度、结束状态和随机源位模式。
- `captureJukeboxes.py`：151 刻 / 68 点验证所有唱片的插入、重写、清空、供电、比较器与感测体；另一场景 1,456 刻 / 11 点验证漏斗插入、下方锁定、曲终抽取、空槽条件与注册变化，逐刻比较播放进度。
- 原生专项验证六向投掷器、非法库存、快照续播、原始状态暂停、空闲休眠及队列一致性。Release 与 ASAN/UBSAN 共 79 项通过。
- `jukeboxTests.py` 验证服务协议、JavaScript JSON 往返、曲终保留读数和漏斗释放；既有钟、音符盒、振动、投掷器与完整服务流程回归通过。
- 浏览器手工放置并插入 `bounce`，单步显示 1 gt / 直接供电 15 / 唱片读数 8；清空后归零，撤销后从原进度续播至 3 gt，控制台无错误。修复环境与库存面板共用 React 标识导致刷新时重复显示的问题。

固定版本原版源码、JAR 和音频不随项目分发。
