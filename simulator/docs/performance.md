# 性能测量

以下数字只代表给定工作负载，不能推出所有红石机器的速度，也没有与原版 Minecraft 作倍率比较。

## 2026-09-07：区块查询缓存

环境：Apple M1、8 逻辑核心、16 GiB 内存、macOS 15.7.4，Apple Clang 17 的 arm64 Release 构建。浏览器保持暂停；测试不含三维渲染和探针。

工作负载为 10,000 条独立拉杆—粉线—中继器—粉线—灯电路，含支撑共 110,000 方块。每条电路接受 40 次输入翻转，累计执行 320 游戏刻。计时包含输入改变、核心执行、收集显示增量，排除搭建初始化。每次都有 600,000 个计划事件、55,200,000 次邻居更新，不以空闲跳跃充当活动吞吐。

| 版本 | 三次耗时（秒） | 中位耗时 | 中位吞吐 |
| --- | --- | --- | --- |
| `84ce470` | 3.369 / 3.393 / 3.409 | 3.393 s | 94.3 gt/s |
| 区块缓存 | 2.208 / 2.174 / 2.243 | 2.208 s | 144.9 gt/s |

中位耗时下降约 35%。原始样本、源文件校验值和测量限制保存在 [chunkCacheM1.json](../tests/benchmarks/chunkCacheM1.json)。普通桌面环境存在调度、温度和后台活动影响；这组数据没有绑核或控制温度。

五秒原生 CPU 采样显示邻近方块查询及哈希查找是明显热点。`World` 因此增加 8 项直接映射的区块指针缓存，也记录不存在的区块。缓存存指针，不缓存信号或方块值；原来的更新次序和次数不变。

区块由独立 `unique_ptr` 持有，哈希表扩容不移动区块。创建、修改、删除区块同步刷新对应缓存项，清空、复制和所有权转移不会保留旧世界指针。新增测试覆盖负坐标、缓存空查询后插入、哈希表扩容、删除、复制及移动；全部 27 项 Release 与 ASAN/UBSAN 测试通过，四组原版差分结果不变。一个世界由一个线程独占，其他线程需要独立快照，不能并发操作此缓存。

扩展到 1,100,000 方块的单次缓存版运行耗时 28.575 s（11.2 gt/s），处理 6,000,000 个计划事件和 552,000,000 次邻居更新。它说明大规模活动电路仍有明显优化空间，不能据此宣称百万活动方块达到实时。

## 重跑

先完成 Release 构建，再在仓库根目录执行：

```sh
python3 simulator/tools/runBenchmarks.py --circuits 10000 --runs 3 --output simulator/testResults/myBenchmark.json
```

脚本保存原始样本、中位数、平台、Git 状态和可执行文件 SHA-256。结果文件已存在时拒绝覆盖。测试前应暂停编辑器仿真，不要同时构建或运行其他负载。日常运行不需要原版 Minecraft。

仍需验收的项目包括混合器件工作负载、64 探针开销、20,000 可见方块的渲染、暂停延迟、通信背压和完整内存预算。当前数据不代表全部设计指标达成。
# 调度修正后的复测

2026-09-07 在同一 M1 开发机、11 万方块 / 1 万电路的相同工作负载上，修正分区块批量收集后测得 2.339208、2.430844、2.367239 秒，中位数 2.367239 秒，即约 135.2 gt/s。仍为 60 万计划事件、5,520 万邻居更新。原始数据见 `tests/benchmarks/tickSchedulerM1.json`。这比前次缓存版本的 2.208 秒中位数慢，正确的调度语义带来额外队列成本；该阶段没有宣称进一步提速，也没有达到设计中的全部性能目标。

## 不限速与界面统计

不限速运行使用 `advanceActive`，只推进到实际待执行事件；队列耗尽后立即停在最后一个事件的游戏刻。不会再为了填满一批任意的 100,000 gt 而推进空闲时间。显式“前进 N 刻”和固定速度仍使用 `advanceTo`，允许实验时间前进到指定时刻；两者的时间语义不同。

状态栏显示连续运行期间的“事件/s”，来自实际执行的计划刻、方块事件和方块实体/接触回调数量，按墙钟时间测量。手动编辑、单步及无事件的空闲跳跃不计入该指标；暂停时显示 0。它不等于每秒邻居更新数，也不能直接用于比较两个器件组成不同的电路。速度菜单的 gt/s 仍然是目标游戏时间倍率。

正式性能结论继续使用上面的固定工作负载、事件数和耗时，不能从界面瞬时统计推导相对 Minecraft 的倍数。
