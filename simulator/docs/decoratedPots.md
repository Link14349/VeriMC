# 饰纹陶罐

饰纹陶罐采用一个真实库存槽，容量遵循默认物品堆叠上限：石头 64、雪球 16、木剑 1 等。比较器按该槽实际填充率输出 0–15；上方实体方块不会阻挡读数。六个方向均可由投掷器插入，漏斗可从上方陶罐抽取或向朝向的陶罐插入；满罐和不同物品不会强行合并。

原版陶罐的单槽容器在 `setItem` / `removeItem` 内不调用 `setChanged`，成功传输由传输代码通知。受阻漏斗尝试移除再恢复时没有可观察通知，内核可休眠；接收方容量、源库存、拓扑或供电变化局部唤醒。不能把普通箱子取物失败时仍存在的通知套用到陶罐。

编辑器提供单槽库存、比较器读数、程序绘制的陶罐外观及快照/撤销。朝向和开裂状态编辑保留库存，移除后清除内部数据。

当前为部分支持：尚未加入玩家持物逐件插入、摇晃方块事件、声音、游戏事件、投射物击碎及内容散落反馈；未模拟陶片装饰、战利品表和流体系统。库存编辑是明确的编辑操作，不等同于完整玩家交互。带自定义组件的物品明确拒绝。

## 验证

`capturePots.py`：73 刻 / 26 点原版 GameTest，比较方块状态、模拟读数及库存。覆盖四个朝向、64/16/1 堆叠物品的全部有效数量、上方遮挡、六向投掷器、漏斗过滤/满罐/容量唤醒、清空与移除。

原生专项验证受阻漏斗推进 10,000 刻只执行一次检查，没有伪造波形边沿；释放容量后抽取、输出更新和快照恢复一致。协议测试覆盖单槽读写、越界拒绝、撤销及快照。浏览器实操石头 64 件输出 15，清空输出 0，并检查撤销恢复与控制台错误。

依据固定 26.2 的 `DecoratedPotBlock`、`DecoratedPotBlockEntity`、`ContainerSingleItem` 和 `HopperBlockEntity`。正常使用无需 Minecraft 安装。
